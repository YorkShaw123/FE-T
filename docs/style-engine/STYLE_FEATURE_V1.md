# Style Feature V1 技术规格

> 状态：**Frozen**  
> 版本：`style_feature_version = 1`  
> 冻结日期：2026-08-14  
> 适用范围：现代中文为主，允许夹杂英文和数字

## 1. 目标与非目标

V1 用 44 个确定性数值描述文本的表层文风，覆盖节奏与长度、标点习惯、功能词与基础句法代理。实现必须完全本地、CPU 极轻，不调用 LLM、Embedding、网络或数据库。

V1 不判断主题、情绪、文学流派、作品质量或作者身份，也不承担检索和 Prompt 组装。所有“结构”指标都是可解释的规则代理，不等同于完整中文分词、词性标注或句法分析。

任何会改变同一文本 raw 值的切分规则、词表、阈值或公式都必须提升版本；V1 不得原地改变语义。

## 2. 稳定输出契约

推荐公开 API：`analyze_style_features(text: str) -> dict`。非字符串输入应抛出 `TypeError`；字符串输入永不因内容为空、过短或只有标点而失败。

```json
{
  "style_feature_version": 1,
  "statistics": {
    "valid_char_count": 0,
    "sentence_count": 0,
    "paragraph_count": 0
  },
  "features": {
    "rhythm.sentence_length.mean": null
  }
}
```

- `features` 必须始终包含全部 44 个稳定 ID。
- raw 值为 JSON number 或 `null`；不得返回 NaN/Infinity。
- 样本不足或公式无定义时返回 `null`，不能用 `0` 冒充。
- `0` 是有效值，例如足够长的文本中没有问号。
- V1 只输出 raw Feature；权重和归一化元数据用于未来 Style Diff，不要求 Analyzer 输出 normalized 值。
- 浮点计算使用 Python 双精度，公开值四舍五入到小数点后 6 位；整数计数放在 `statistics`。

## 3. 统一文本规则

### 3.1 空白与 Unicode

1. 移除字符串开头的 BOM `U+FEFF`；`CRLF` 和 `CR` 统一为 `LF`。
2. 行内制表符、全角空格、不换行空格和连续 Unicode 空白折叠为一个普通空格；行首尾空白移除。
3. 空白不计入有效字符、句长、段长或每千字分母；换行只参与段落识别。
4. 不做全局 NFKC/NFC 字形折叠，避免丢失全角/半角标点习惯；识别器显式兼容两种标点。

### 3.2 有效字符与每千字

有效字符数记为 `N`：Unicode 类别以 `L` 开头的字母和类别 `Nd` 的十进制数字各计 1。汉字计 1；英文 `style` 计 5；`2026` 计 4；组合附加符、emoji、标点、符号和空白计 0。

所有“次/千字”统一表示每千有效字符：

`rate_per_kchar = occurrence_count / N * 1000`

### 3.3 段落

- 规范化后的每个非空物理行是一个段落；连续空行不产生空段。
- 段长是段内有效字符数。
- V1 不猜测并合并排版软换行；导入层可预先清洗，但 Analyzer 必须按收到的文本统计。

### 3.4 逻辑标点标准化

- 最大连续省略号串：`…`、`⋯`，或不少于 3 个连续 `.`/`．`，统一为一个 `ELLIPSIS` Token；夹在两个 ASCII 数字之间的点串不算省略号。
- 最大连续破折号串：`—`、`–`、`―`，或不少于两个连续 `-`，统一为一个 `DASH` Token；单个 `-` 不算破折号。
- 连续问号、感叹号及其混合串（如 `？？`、`!!!`、`？！`）产生一个句界，但问号和感叹号分别按“是否在该串出现”各计一个 Token。因此 `？！` 的问号频率和感叹号频率各增加 1。
- 逗号识别 `，,`；句号识别 `。` 及满足切句规则的 `.`；分号识别 `；;`；冒号识别 `：:`。
- 括号支持 `（）()[]【】〔〕`：一个成功配对计一次；未配对的单个括号也计一次。

### 3.5 引号

- 支持 `“”`、`‘’`、`「」`、`『』`、半角双引号，使用栈做同类配对并允许嵌套。
- 引号内文本正常参与所有统计和切句。
- 引号覆盖率分子是全部成功配对区间内有效字符的并集，嵌套部分只计一次。
- 未配对引号不产生覆盖区间，避免残缺开引号覆盖后续全文。
- 终止标点位于闭引号前时，紧随的闭引号归入前一句。

### 3.6 中文切句

按段落独立扫描：

1. `。！？!?` 是终止标点；连续终止标点串只产生一个句界。
2. 每个逻辑 `ELLIPSIS` 产生一个句界，即使作者可能把它用作句内停顿；这是 V1 的确定性取舍。
3. 半角 `.` 仅在不位于两个 ASCII 字母/数字之间，且后面只有闭引号/闭括号、空白或段末时切句。小数、版本号、域名和英文缩写中的点不切句。
4. 终止标点后的连续闭引号/闭括号归入前一句。
5. 段末无终止标点的残片包含至少 2 个有效字符时计为一句；不足 2 个字符不计句子，但仍计入段长和 `N`。
6. 句长只计算有效字符。

### 3.7 句长阈值和统计方法

- 短句：`L <= 12`；中等句：`13 <= L <= 29`；长句：`L >= 30`；超长句：`L >= 50`。
- 超长句同时属于长句。
- 中位数按通常定义；偶数样本取中间两项平均。
- P25/P75 使用线性插值：`h=(n-1)*p`，在相邻排序值间插值。
- 标准差使用总体标准差 `ddof=0`。
- CV 为总体标准差除以均值；均值为 0 时缺失。

## 4. 功能词和句法代理词典

同一词典内按当前位置最长匹配，命中后游标前进至词尾，避免 `没有` 同时计作 `没有` 和 `没`。不同 Feature 独立扫描。引号内外一视同仁。

| 类别 | V1 冻结词典/规则 |
|---|---|
| 否定 | `没有、不是、不能、不会、不要、并非、未曾、不、没、无、未、勿、别、莫、非` |
| 转折 | `但是、然而、可是、不过、反而、尽管、虽然、但、却、只是` |
| 因果 | `因为、因此、所以、因而、由于、故而、从而、于是` |
| 条件 | `如果、要是、只要、除非、假如、倘若、一旦、若是` |
| 时间推进 | `与此同时、片刻后、不久后、随后、然后、接着、继而、后来、转眼、次日、翌日` |
| 推测/模糊 | `似乎、仿佛、好像、大概、或许、也许、可能、约莫、隐约、隐隐` |
| 程度副词 | `非常、极其、十分、相当、格外、尤其、有些、很、太、极、更、最、颇、稍、略` |
| 语气词 | `罢了、吗、呢、吧、啊、呀、嘛、哦、啦、呗`；仅在后方到分句/句末之间只有空白、闭引号/闭括号和标点，或直接到段末时计数 |
| 第一人称 | `我们、咱们、俺们、咱、俺、我` |
| 第三人称 | `他们、她们、它们、他、她、它` |
| 把字代理 | 每个 `把` 计一次；紧接在 `一、两、几、这、那、哪、每` 后的量词用法不计 |
| 被字代理 | 每个 `被` 计一次；`被子、被褥、被单、棉被` 中的 `被` 不计 |

`的/地/得/了/着/过` 直接按字形出现次数计算，明确不做词性消歧。

## 5. Feature 注册表

记 `S` 为句数、`P` 为段数、`L_i` 为句长、`G_j` 为段长、`C(x)` 为 Token/词典命中次数。最小样本不满足时返回 `null`。长度影响中的“低”表示已比例化，但短文本仍有抽样方差。

|---|---|---|---|---|---:|---|---|---|
| `rhythm.sentence_length.mean` | 平均句长 | `sum(L)/S` | 字符/句 | `S>=5` | 0.7 | 低；短样本波动 | `[0,80]` | 高：整体偏长，拆分多中心句；低：整体偏短，合并逻辑连续短句 |

| `rhythm.sentence_length.std` | 句长标准差 | `sqrt(sum((L-mean)^2)/S)` | 字符 | `S>=10` | 0.6 | 低；短样本波动 | `[0,60]` | 高：绝对起伏过强，收敛极端句；低：句长过齐，加入长短变化 |

## 6. 异常值、缺失值和归一化

- 每项表中的固定区间使用 `normalized=(clamp(raw,min,max)-min)/(max-min)`。
- raw 永远保留真实计算结果；只有未来 normalized 值截断到 `[0,1]`。
- 不删除极端文本，极端值可能是真实风格。
- 最小样本不足：`null`；分母为 0：`null`；足够样本但计数为 0：`0`。
- 缺失值不填补、不参与距离；未来权重在双方共同可用 Feature 内重新归一化。
- `too_high/too_low` 只表示待比较文本相对目标语料偏高/偏低，不是质量评价。

## 7. 共线性审查与聚合约束

V1 为解释性保留部分相关指标，但总距离不得简单累加 44 项：

| 相关簇 | 明显关系 | 处理 |
|---|---|---|
| mean/median/P25/P75 | 都描述句长位置 | mean 降权；簇内先聚合 |
| std/CV/相邻句变化 | 都描述节奏波动 | std 降权；保留绝对、相对、局部三种解释 |
| 短/长/超长比例 | 超长包含于长句 | 超长降权；不得重复生成建议 |
| 平均段长/平均句长/每段句数 | 近似乘法关系 | 使用类别预算，不直接求和 |
| 总标点/各标点频率 | 总量由子项构成 | 总标点降权为 0.5 |
| 逗号/句号比与两项频率 | 比率由子项决定 | 三项最多生成一条同义建议 |
| 引号覆盖/问叹号/语气词 | 对话中共同升高 | 保留解释，提示层合并 |
| 人称代词与叙述视角 | 受体裁和 POV 影响 | 不作为质量指标，不与 Style Card 重复计权 |

未来一级类别预算初始值：节奏与长度 `0.38`、标点 `0.27`、功能词与基础句法 `0.35`。这是未来 Style Diff 的聚合约束，不属于 Analyzer raw 输出。

## 8. 与现有实现的边界

- `style_rag_service.py` 的 200～900 字语义切片不是本规格的自然段边界。
- `style_profile_service.py` 和 `style_excerpt_service.py` 的 LLM 标签不属于 V1 Feature，也不能填补缺失值。
- Analyzer 应作为职责单一的新 service；不得访问数据库、RAG 检索、Prompt Assembler、LLMClient 或网络。
- 本阶段只冻结文档，不实现服务、路由、数据库或 UI。

## 9. M2 必须覆盖的测试矩阵

- 中文普通叙述，以及具体句长/段长/标点值；
- 大量短句、长句和超长句的阈值边界；
- 对话与嵌套/残缺引号覆盖率；
- `…/……/...`、`—/——/--` 和重复 `？！!!!`；
- 第一/第三人称最长匹配，避免“我们”重复计“我”；
- 每组功能词、最长匹配、语气词位置和把/被排除项；
- 空文本、极短文本、纯标点、混合中英数字；
- 44 个 ID 始终存在、无 NaN/Infinity、结果确定性；
- 不导入数据库、LLM 或网络客户端；
- 百万有效字符的线性时间和合理内存基线。
