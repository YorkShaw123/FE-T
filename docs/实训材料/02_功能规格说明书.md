# 雨生编辑器（Flora Editor）功能规格说明书（Spec）

> 版本：v1.0 ｜ 基于项目实际代码编写，所有接口与表结构均可在 `server/` 源码中对应。

## 一、架构设计

### 1.1 总体架构

```
┌─────────────────────────────────────────────────┐
│  Tauri 2 桌面壳（Rust，仅 177 行）                │
│  · 拉起 Flask Sidecar 子进程                      │
│  · 健康检查 /api/health                           │
│  · WebView 加载页面，进程随窗口关闭而清理          │
├─────────────────────────────────────────────────┤
│  前端层（原生 JS，无框架）                         │
│  server/templates/index.html + server/static/js/  │
│  16 个模块：generation / templateManager /        │
│  styleCard / styleCorpora / history / state 等    │
├─────────────────────────────────────────────────┤
│  路由层（Flask Blueprints，4 组 / 51 端点）        │
│  template_bp / generation_bp / style_bp /         │
│  style_corpora_bp                                 │
├─────────────────────────────────────────────────┤
│  服务层（server/services/）                       │
│  prompt_assembler（提示词组装）                    │
│  generation_service（六阶段生成流水线）            │
│  api_client（8 家 LLM 统一适配）                   │
│  style_rag_service（混合检索+重排）                │
│  style_engine（44 项文风特征本地分析）             │
│  去AI味 / 风格重写 / 内容复用检测                  │
├─────────────────────────────────────────────────┤
│  数据层（SQLite + SQLAlchemy ORM）                │
│  8 张表 + 幂等迁移机制（database/migrations.py）   │
└─────────────────────────────────────────────────┘
```

### 1.2 关键设计决策

| 决策 | 理由 |
|------|------|
| Tauri 2 而非 Electron | Rust 壳只负责进程管理，复用系统 WebView，体积与内存远低于捆绑 Chromium |
| Flask Sidecar 而非 Rust 全栈 | AI 生态在 Python 侧最成熟；Rust 只做壳，职责单一 |
| 原生 JS 而非 React/Vue | 单页应用规模可控，避免构建链与框架升级负担 |
| SQLite 而非向量数据库 | 单机单用户场景够用；向量以 BLOB 存表内，NumPy 计算相似度 |
| API Key 不落盘 | Key 由前端输入、仅随请求体传递，不写数据库/localStorage |

### 1.3 生成流水线（核心链路）

```
用户点击生成
   │ POST /api/generation/generate-stream（SSE）
   ▼
① 组装提示词   prompt_assembler 合并启用的模板+变量
   ▼
② 初稿生成     api_client 流式调用 LLM，SSE 逐字推送前端
   ▼
③ RAG 检索     style_rag_service 混合检索语料库 Top-4 片段
   ▼
④ 风格重写     注入检索片段 + Style Card，二次调用 LLM
   ▼
⑤ 去AI味       按去AI味提示词第三次调用，消除机械感
   ▼
⑥ 落盘归档     GenerationRecord 写入四个版本字段
```

- **并发控制**：`operation_guard` 互斥，同一时刻仅允许一条生成流水线。
- **SSE 模式**：先建立连接后干活，前端实时呈现各阶段进度与流式文本。

## 二、数据库设计

数据库：本地 SQLite（`data/` 目录），ORM 为 SQLAlchemy，共 **8 张表**，变更一律走 `server/database/migrations.py` 的幂等迁移。

| 表名 | 中文名 | 职责与关键字段 |
|------|--------|----------------|
| `prompt_templates` | 提示词模板 | 模板内容、分类、变量、启用状态；`version`+`parent_id` 构成版本树 |
| `style_profiles` | 文风卡 | 绑定模板，`source_hash` 检测源文过期，分析结果存 `card_json` |
| `style_excerpts` | 文风范例片段 | 范例文章拆分的片段，带场景/视角/情感/对话密度等标注 |
| `style_corpora` | 文风语料库 | 导入语料的元信息：字符数、块数、索引状态、Embedding 模型信息 |
| `author_style_profiles` | 作者文风画像 | 语料库聚合分析出的 44 项特征画像 + 置信度 |
| `style_chunks` | 语料块 | 语料切块：内容哈希、文风特征 JSON、场景标签、Embedding 向量（BLOB） |
| `generation_records` | 生成记录 | 四版本内容（`content`/`deai_content`/`style_rewrite_content`/`edited_content`）、编辑历史、评分、置顶、使用的模板与变量快照 |
| `project_settings` | 项目配置 | KV 配置存储（主题等非敏感项） |

**设计要点**：
- 每次生成**同表多字段**留存四个版本，天然支持版本对比视图，无需关联查询。
- 模板使用 `parent_id` 自引用 + 版本号，实现不可变版本链，回滚即指向历史节点。
- `style_chunks.embedding_blob` 直接存二进制向量，配合 SQLite 索引完成本地检索，不引入外部向量库。

## 三、API 接口设计

REST 风格，统一前缀 `/api`，JSON 通信；生成链路使用 SSE。共 4 组蓝图、51 个端点。

### 3.1 模板管理 `/api/templates`（16 个）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` `/grouped` `/<id>` | 列表 / 按分类分组 / 详情 |
| POST | `/` `/starter` | 新建 / 载入入门模板 |
| PUT | `/<id>` | 编辑（自动生成新版本） |
| DELETE | `/` `/<id>` `/all` | 删除单个 / 全部 |
| POST | `/<id>/toggle` | 启用/停用 |
| GET | `/<id>/versions` | 版本历史 |
| POST | `/<id>/restore/<version_id>` | 回滚到指定版本 |
| POST | `/export` / `/import` | 导出 / 导入 |

### 3.2 文章生成 `/api/generation`（12 个）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/generate` | 同步生成 |
| POST | `/generate-stream` | **SSE 流式生成**（六阶段流水线，核心接口） |
| POST | `/preview-prompt` | 预览组装后的最终提示词 |
| POST | `/transform-text` / `/extract-text` | 文本转换 / 提取 |
| GET | `/models` `/categories` `/default-deai-prompt` | 可用模型 / 分类 / 默认去AI味提示词 |
| GET/PUT/DELETE | `/records[/<id>]` | 生成记录查询、保存编辑、删除 |

### 3.3 文风卡 `/api/style-profiles`（9 个）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET/PUT | `/<template_id>` | 查看 / 更新文风卡 |
| POST | `/<template_id>/analyze` `refresh` | 分析范例文章 / 刷新 |
| POST | `/<template_id>/restore` | 恢复 |
| GET | `/<template_id>/excerpts` | 范例片段列表 |
| POST | `/<template_id>/excerpts/rebuild` | 重建片段 |
| PUT/DELETE | `/<template_id>/excerpts/<id>` | 编辑 / 删除片段 |

### 3.4 文风语料库 `/api/style-corpora`（14 个）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET/POST | `` | 语料库列表 / 创建 |
| GET/PUT/DELETE | `/<corpus_id>` | 详情 / 更新 / 删除 |
| POST | `/<corpus_id>/import` | 导入语料文本 |
| POST | `/<corpus_id>/index` | 建索引（本地向量化） |
| GET | `/<corpus_id>/index-progress` | 索引进度轮询 |
| POST | `/<corpus_id>/clear` | 清空索引 |
| GET | `/<corpus_id>/chunks` | 分块列表 |
| POST | `/search` | 混合检索（关键词+向量） |
| GET/POST | `/embedding-config` `/embedding-model/*` | 本地 Embedding 模型状态 / 安装 / 进度 |

**约定**：所有响应统一 `{"code", "message", "data"}` 结构；错误返回对应 HTTP 状态码 + 中文可读 message；API Key 仅出现在生成类请求体中，响应与日志均不回显。

## 四、审查报告

### 4.1 测试覆盖

| 项目 | 结果 |
|------|------|
| pytest 测试文件 | 20 个 / 3,365 行，覆盖 10 个测试域（模板、生成、文风卡、语料库、检索、复用检测、迁移、API 合同等） |
| Style Engine 质量 | 三层体系：特征单元测试 → 相似度/检索集成测试 → 固定样本基准测试（`docs/style-engine/` 下 BENCHMARK） |
| CI | GitHub Actions：pytest + Ruff 全绿后方可合并 |

### 4.2 安全审查

| 风险项 | 措施 | 结论 |
|--------|------|------|
| API Key 泄露 | 仅内存传递，不写库/不写 localStorage/不写日志 | ✅ 通过 |
| 数据隐私 | SQLite 纯本地；用户数据库与真实生成记录在 `.gitignore` 中排除 | ✅ 通过 |
| 语料版权 | 基准测试仅用可公开再分发或程序生成样本；私人语料走本地忽略路径 | ✅ 通过 |
| Web 安全 | CSP 响应头控制 frame-ancestors，防预览页被第三方嵌套 | ✅ 通过 |
| 输入校验 | 路由层参数校验 + 统一异常处理，错误信息不泄露堆栈 | ✅ 通过 |

### 4.3 代码质量

- **静态检查**：Ruff（Python）零告警；Rust 层 `cargo build` 无 warning。
- **架构一致性**：严格 services / routes / database 三层，路由不写业务、服务不碰 HTTP。
- **兼容性**：文章生成 API、Style RAG API 及历史数据向后兼容；数据库变更全部经幂等迁移，老库升级无损。
- **文档完备**：README、架构、开发、构建、排障、Style Engine 专项（README/ARCHITECTURE/EXEC_PLAN/STYLE_FEATURE_V1/BENCHMARK）等 13 篇文档与代码同步。

### 4.4 已知限制

1. 首次使用需自备 LLM API Key（产品设计取向，非缺陷）。
2. 仅支持 Windows（Tauri 目标平台）；macOS/Linux 理论可移植但未验证。
3. 本地 Embedding 模型首次索引需下载模型文件，耗时与网络相关。
