# 雨生编辑器（Flora Editor）项目介绍文档

## 一、项目名称

**雨生编辑器（Flora Editor）** —— 一款 Windows 本地优先的 AI 长文写作编辑器。

> 取名"雨生"，寓意文字如雨滋养而生：AI 不替你写，而是顺着你的文风生长。

## 二、业务场景

### 2.1 目标用户

| 用户群体 | 典型场景 |
|---------|---------|
| 网文/小说作者 | 日更压力大，需要保持个人文风的前提下提升产量 |
| 自媒体创作者 | 多平台内容生产，需要稳定可复用的写作框架 |
| 文案/策划从业者 | 反复打磨品牌调性文案，提示词散落在聊天记录里 |
| 重隐私写作者 | 不愿把未发表稿件和 API Key 交给云端服务 |

### 2.2 解决的三大痛点

1. **提示词难复用**——好的提示词淹没在聊天记录里，每次重写。
   → 模板库 + 变量系统 + 版本树，提示词资产化管理。
2. **AI 文风机械**——生成内容一股"AI 味"，与个人文风割裂。
   → Style Engine 本地分析 44 项中文文风特征 + Style RAG 语料检索，双路注入生成链路。
3. **隐私与成本顾虑**——稿件上云、Key 托管、平台订阅费。
   → 纯本地 SQLite 存储，API Key 仅在内存中随请求传递、永不落盘，按需自购 API 额度。

## 三、核心功能

| # | 功能 | 说明 |
|---|------|------|
| 1 | **模板管理** | 提示词模板的增删改查、分类分组、变量占位、启用组合、版本历史与一键回滚、导入导出 |
| 2 | **文章生成** | 六阶段流水线：组装提示词 → 初稿流式输出（SSE 逐字呈现）→ Style RAG 检索注入 → 文风重写 → 去 AI 味 → 落盘归档 |
| 3 | **Style RAG 语料库** | 导入个人作品 → 自动分句切块 → 本地向量化建索引 → 生成时混合检索（关键词+向量）注入最相关的 4 个片段 |
| 4 | **Style Card 文风卡** | 上传承载文风的范例文章 → 本地 44 项特征分析生成文风卡 → 注入生成链路，源文变更自动检测过期 |
| 5 | **生成记录** | 每次生成归档四个版本（初稿 / 去AI味 / 风格重写 / 人工编辑），支持对比视图、评分、置顶、笔记 |
| 6 | **多模型接入** | 适配 DeepSeek、通义千问、智谱 GLM、Kimi、OpenAI 等 8 家厂商协议，统一调用层 |
| 7 | **桌面级体验** | Tauri 2 封装为 Windows 桌面程序，Sidecar 进程生命周期与窗口绑定，关闭即清理 |

## 四、案例特点

1. **本地优先（Local-First）架构**：所有用户数据存于本机 SQLite，不依赖任何云端服务；LLM 调用是唯一出网行为，且用户可自由选择厂商。
2. **文风是核心竞争力**：区别于通用 AI 写作工具，本项目把"让 AI 写得像你"做成可量化的工程问题——44 项中文文风特征（句长节奏、标点习惯、对话密度、意象偏好等）+ 语义检索，全部本地计算，零额外 API 成本。
3. **内容复用三道防线**：哈希精确匹配 → 归一化指纹 → 语义相似度检测，防止 RAG 检索片段被原样搬进生成结果，避免"抄袭自己"。
4. **轻量克制的技术选型**：Rust 层仅 177 行（只做进程管理），前端零框架原生 JS，不引入向量数据库和深度学习运行时，发行包体积和内存占用远低于 Electron 方案。
5. **AI 深度参与开发本身**：项目以 Trae + DeepSeek V3 Pro 为主力、VSCode + Codex 为审查辅助的 Vibe Coding 模式，21 天独立完成 18,425 行代码、20 个测试文件、13 篇技术文档——AI 既是产品能力，也是开发手段。
6. **工程规范完备**：幂等数据库迁移、SSE 流式通信、并发互斥守卫、CI 流水线（GitHub Actions）、Ruff 静态检查 + pytest 全绿。
