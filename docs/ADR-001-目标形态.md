# ADR-001：目标形态定为「本地服务 + 浏览器」

- 状态：已采纳
- 日期：2026-11-14
- 决策人：项目所有者
- 影响范围：整个项目形态、构建与发布方式

## 背景

项目原本是 Windows 桌面程序（Tauri 2 + Flask Sidecar + PyInstaller 单文件后端）。
2026-11 起完成了一次 Agent 架构重构：后端改写为 `backend/` 包（FastAPI + LangGraph +
三层兜底 + 三张 Agent 图），59 个端点在双轨下全部可达。

重构到打包环节时遇到一个不可回避的问题：桌面形态要求把 LangChain/LangGraph 一并
冻结进单文件 exe，产物从 38MB 涨到 51MB，且冻结运行态出现"启动即安静退出"。
继续排查需要投入时间，而这个投入**只服务于一个已经不再需要的形态**。

## 决策

**新应用的正式形态是「本地服务 + 浏览器」**：

- 后端以源码方式运行：`python run_server.py`（读 `FLORA_PORT`，默认 5000）。
- 用户用浏览器访问 `http://127.0.0.1:<port>`；前端仍是由后端直接提供的同一套页面。
- 桌面端（Tauri 壳、NSIS 安装包、PyInstaller 冻结包）**退役，不再作为验收项**。
  `src-tauri/`、`flora-server.spec`、`run_server.py` 的冻结适配保留在仓库里，
  但不再维护、不再验证。

## 选择它的理由

1. 与现有代码契合度最高：前端本来就是后端托管的静态页，`backend/` 已经在 `/` 提供首页，
   形态切换不需要重写任何界面代码。
2. 兑现架构价值最快：不用再为"装进 40MB"做技术妥协，LangChain、向量库、PostgreSQL
   这些服务端能力随时可以接。
3. 可逆性好：将来若要回到桌面，只需要重新打包，业务代码不用动。

## 被放弃的方案

**单机 Docker**：能顺手带上 PostgreSQL / Milvus，但用户要先装 Docker，Windows 体验差，
对当前"一个人用、数据在本地"的场景属于过度工程。

**服务器部署**：真正的多人形态，但立刻带出鉴权、多租户、数据隔离、并发配额，
至少再加两三周，且与"语料不上传"的产品性格冲突。留作远期选项。

## 后果

- 运行基准从"双击 exe"变成"一条命令起步"，需要提供启动脚本与依赖安装说明。
- 不再受桌面体积约束；引入依赖时只考虑运行正确性与可维护性。
- 旧 Flask 后端（`server/`）在本次决策后**删除**，其 59 个端点的存在性由
  `tests/test_api_contract.py` 锁定。
- 需要重新对齐的欠账：统计画像服务（`style_score` 仍固定为 0）、embedding 运行时
  （索引不产向量）、风格基准脚本（依赖画像服务，暂从仓库移除）。

## 复审条件

出现以下任一情况时重新评估：需要多人协作使用；需要跨设备访问；需要把生成任务放到
服务器上跑；或者本地服务模式在真实使用中暴露出口径问题（比如端口冲突无法解决）。
