# 任务一：项目阐述

## 一、项目概述

**雨生编辑器（Flora Editor）** 是一款面向中文文字与小说创作的 Windows 本地 AI 编辑器。它将人物、背景、剧情、范例和其他约束整理成可复用模板，通过可视化生成链路组合提示词，并调用用户选择的大语言模型生成和修改文章。所有数据保存在本机 SQLite，API Key 仅在请求中传递、不落盘存储。

> 产品定位：**本地桌面工具**，不提供 Web、SaaS 或远程自托管能力。浏览器入口仅限 `127.0.0.1` 本机开发测试。

---

## 二、设计目的

### 2.1 痛点分析

中文创意写作（尤其是网络小说、同人创作）在使用大语言模型辅助时存在三个核心痛点：

| 痛点 | 具体表现 | 本项目解决方式 |
|------|---------|---------------|
| **提示词难以复用** | 每次写作都要重新拼凑人物设定、背景、剧情约束 | 模板管理系统：按分类保存、按需启用、版本控制 |
| **AI 生成文风机械** | "然而"、"综上所述"等 AI 味严重，风格不连贯 | 本地 Style Engine + Style RAG 文风语料检索 + 去 AI 味处理 |
| **隐私与成本顾虑** | 在线平台需上传作品、订阅付费、数据不可控 | 纯本地运行、用户自带 API Key、数据不出本机 |

### 2.2 预期结果

- 用户在桌面双击 EXE 即可使用，无需安装 Python/Node.js/Rust 环境
- 可对接 8 家主流 LLM 服务商（DeepSeek、OpenAI、Kimi、通义千问、智谱、Gemini、Grok、硅基流动），按需切换模型
- 支持导入百万字级参考语料，生成时自动检索 3~5 个文风匹配片段注入提示词
- 本地 Style Engine 在 CPU 上完成中文文风分析，无远程依赖即可降级运行
- 生成记录、版本对比、全屏 Markdown 编辑器形成完整创作闭环

## 三、技术栈

### 3.1 技术选型总览

| 层次 | 技术 | 版本 | 用途 |
|------|------|------|------|
| 桌面外壳 | Tauri 2 (Rust) | ^2.5 | 窗口管理、Sidecar 生命周期、系统资源调用 |
| 后端服务 | Flask | 3.1.1 | HTTP 路由、业务逻辑、模板渲染 |
| ORM | Flask-SQLAlchemy | 3.1.1 | 数据库模型映射与查询 |
| 数据库 | SQLite | 内置 | 模板、生成记录、文风语料、向量 BLOB |
| 数值计算 | NumPy | 2.0.2 | 余弦相似度矩阵运算 |
| 文档解析 | olefile | 0.47 | DOC/DOCX 文本提取 |
| 前端 | 原生 JS/CSS/HTML | — | 无框架、无构建步骤，Flask 直接服务 |
| AI 通信 | urllib (标准库) | — | OpenAI 兼容协议，替代 SDK 减小打包体积 |
| 本地 Embedding | ONNX Runtime CPU + BAAI/bge-small-zh-v1.5 | — | 可选语义向量辅助信号 |
| 构建 | PyInstaller + Tauri CLI + NSIS | — | 后端打包为 EXE，Tauri 构建安装包 |
| 代码质量 | Ruff + pytest | — | Python 静态检查与自动化测试 |

### 3.2 关键设计决策

**为什么不用 Electron？** Tauri 使用 Rust 构建桌面外壳，安装包体积约 3~5MB（Electron 动辄 80MB+），内存占用更低，且 WebView2 由 Windows 系统提供，不捆绑完整 Chromium。

**为什么不用 React/Vue？** 前端是单页工作台，交互逻辑集中且不需要组件复用生态。使用原生 JS 避免引入 Node 构建链，桌面版与浏览器调试复用同一套静态文件，维护成本最低。

**为什么不用 OpenAI Python SDK？** 该 SDK 依赖 pydantic/httpx/jiter 等，打包后体积增加 15~20MB。项目用标准库 urllib 直接实现 OpenAI 兼容协议（Chat Completions + Embeddings + SSE 流式），体积为零增加。

**为什么不用向量数据库（FAISS/Chroma）？** 4000 条 × 1024 维 float32 矩阵仅占 16MB 内存，NumPy 余弦计算毫秒级完成。引入独立向量库会让 PyInstaller 打包体积暴涨并触发杀软误报，得不偿失。向量以 BLOB 存入 SQLite，检索时一次性加载为 NumPy 矩阵。

## 四、运行流程

### 4.1 桌面版启动流程

```
用户双击 雨生编辑器.exe
  │
  ├─ Tauri 主程序启动
  │    ├─ pick_free_port() → 选择空闲回环端口
  │    ├─ 通过 FLORA_PORT 环境变量启动 flora-server.exe (Sidecar)
  │    └─ wait_for_server() → 轮询等待 Flask 就绪 (最多 60s)
  │
  ├─ Flask 后端就绪
  │    ├─ _migrate_legacy_data() → 首次运行迁移旧数据
  │    ├─ init_db() → 自动建表 + 幂等迁移
  │    └─ 注册 4 个蓝图: template / generation / style / style_corpora
  │
  ├─ Tauri 窗口导航到 http://127.0.0.1:{port}/
  │    └─ Flask render_template('index.html') → 返回工作台界面
  │
  └─ 用户退出 → Tauri 发送 POST /api/system/shutdown → Flask 自行退出
```

### 4.2 文章生成流程

```
用户在工作台配置：
  ├─ 选择 AI 服务 + 填写 API Key
  ├─ 启用模板（人物/背景/剧情/范例/约束）
  ├─ 选择提示词编排模式（兼容/结构化/智能风格链）
  ├─ 可选：启用去 AI 味、风格参考
  └─ 点击"生成文章"
        │
        ▼
  ┌─────────────────────────────────────┐
  │  1. 前置文章压缩                      │
  │     超过 30000 字 → 本地截断或 API 摘要 │
  │     剧情设定模板绝不压缩               │
  ├─────────────────────────────────────┤
  │  2. 提示词组装                        │
  │     按 9 段顺序拼接：                  │
  │     前缀→背景→人物→剧情→范例→约束     │
  │     →前置文章→风格约束→后缀            │
  │     智能模式额外注入 Style Card       │
  ├─────────────────────────────────────┤
  │  3. Token 预算检查                     │
  │     估算总 Token → 超限则拒绝生成      │
  │     预留 2048 安全余量                 │
  ├─────────────────────────────────────┤
  │  4. 调用 LLM 生成初稿                  │
  │     支持 SSE 流式返回                  │
  │     思考模式 reasoning_content 单独提取 │
  ├─────────────────────────────────────┤
  │  5.（可选）去 AI 味处理                │
  │     追加 assistant 初稿 + user 去味指令 │
  │     生成第二版                         │
  ├─────────────────────────────────────┤
  │  6.（可选）Style RAG 风格参考改写       │
  │     以最新正文检索语料库                │
  │     混合检索 → MMR 重排 → 3~5 片段      │
  │     构造受约束的二次改写请求            │
  ├─────────────────────────────────────┤
  │  7. 保存生成记录到 SQLite              │
  │     含初稿/去味稿/风格改写稿/思维链     │
  │     含组装后提示词/模板快照/风格元数据  │
  └─────────────────────────────────────┘
        │
        ▼
  用户查看初稿/最终稿 → 全屏 Markdown 编辑器修改 → 版本对比 → 评分置顶
```

### 4.3 Style RAG 检索流程

```
导入阶段：
  TXT/DOC/DOCX → 文本提取 → 语义切片(200~900字) → 规则打标
    → Style Window 组装 → 本地 Feature 提取 → Author Profile 聚合
    → 可选 Embedding 向量化 → 存入 SQLite (BLOB + JSON)

检索阶段：
  当前写作上下文 → 硬过滤(场景/标签) → 向量余弦 Top-N + FTS5 BM25 Top-N
    → RRF 融合排序 → 内容复用惩罚 → MMR 多样性重排 → 3~5 个片段
    → 注入第二次模型请求（初稿后二次改写）
```

## 五、核心功能清单

| 功能模块 | 说明 |
|---------|------|
| 提示词模板管理 | 5 类分类（人物/背景/剧情/范例/约束），支持版本控制、导入导出、示例模板 |
| 多服务 AI 生成 | 8 家 Provider，模型/思考模式/采样参数可配，支持流式与同步 |
| 智能风格链 | 从范例模板提取 Style Card，按写作场景选择参考片段注入提示词 |
| Style RAG 文风语料库 | 导入大规模文本，切片打标向量化，混合检索 + 内容复用保护 |
| 本地 Style Engine | 44 个中文文风 Feature，句长/标点/功能词/句法，CPU 本地分析 |
| 续写与修改 | 续写/重写/扩写/润色/去 AI 味，可选 RAG 风格参考二次改写 |
| 编辑与历史 | 全屏 Markdown 编辑器、版本对比、生成记录管理、评分置顶 |
| 生成前检查 | Token 预算预估，超模型上下文限制前给出提示 |
| 桌面版构建 | PyInstaller 打包 Flask → Tauri externalBin 分发 → NSIS 安装包 |

## 八、安全设计

| 安全措施 | 实现方式 |
|---------|---------|
| API Key 不落盘 | 仅在当前请求内存中传递，不写入 SQLite/文件/LocalStorage |
| 服务只监听回环地址 | `127.0.0.1`，桌面版用随机空闲端口 |
| 跨站写入拦截 | `before_request` 检查 Origin 头，拒绝跨站 POST/PUT/PATCH/DELETE |
| 安全响应头 | X-Content-Type-Options、X-Frame-Options、Referrer-Policy、Permissions-Policy |
| URL 白名单 | 帮助链接和社区提示词地址由服务端硬编码，不接受客户端传参 |
| 采样参数过滤 | LLMAdapter 按厂商能力过滤不支持的采样参数 |
| 思维链兜底 | 模型把正文混入 reasoning 时自动回显，避免空白成稿 |
