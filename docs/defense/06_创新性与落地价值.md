# 任务六 + 七：功能创新性、技术方案创新 & 落地价值与迭代创新

## 一、功能创新性

### 1.1 相比 GitHub 开源项目的差异化

GitHub 上的 AI 写作工具大多集中在两类：**提示词管理器**（如 awesome-chatgpt-prompts 类项目，只管提示词不管生成）和 **LLM 前端壳**（如各种 ChatGPT 桌面客户端，只管对话不管创作流程）。Flora Editor 的差异点在于**把创作流程当成一等公民**：

| 对比维度 | 典型开源项目 | Flora Editor |
|---------|-------------|--------------|
| 提示词组织 | 平铺列表或文件夹 | **按创作角色分类的模板系统**（人物/背景/剧情/范例/约束五类），带版本树和启用开关 |
| 文风控制 | 无或仅靠 prompt 描述 | **Style Card（量化文风画像）+ Style RAG（语料检索）双路注入** |
| 生成结果 | 单次对话即弃 | **六版本记录链**：初稿→风格重写→去AI味→定稿，每步可审计可回退 |
| 模型接入 | 通常单厂商 | 8 家厂商统一适配，运行时切换 |
| 数据归属 | 云端存储 | 本机 SQLite，API Key 不落盘 |

### 1.2 三个原创性功能设计

1. **去 AI 味流水线**：不是简单地让模型"重写一遍"，而是初稿 → 风格参考重写 → 去 AI 味处理的三段式处理，每段产出的版本都独立保存，创作者可以对比选择。市面上极少有工具把"AI 味"作为独立质量维度来管理。

2. **模板版本树**：模板更新时旧版自动入版本表，支持回滚。这解决了长期创作中"改坏了设定却找不回来"的真实痛点——源自网文作者维护设定集的真实工作习惯。

3. **创作闭环**：生成记录中的满意段落可以一键回写为模板，让提示词资产随使用不断增厚，工具越用越"懂"作者。

## 二、技术方案创新

### 2.1 Style Engine：本地优先的中文文风分析

这是技术上最有辨识度的部分。主流 RAG 方案依赖远程 Embedding API（OpenAI、硅基流动），本项目选择**纯本地路线**：

- **44 个中文统计特征**（句长分布、标点习惯、对话比例、段落节奏等）用 NumPy 在 CPU 上直接计算，零网络依赖、零 API 成本
- **混合检索**：BM25 关键词 + 向量余弦加权融合，对中文短文本比单一向量检索更准
- **可选本地 ONNX 模型**（bge-small-zh-v1.5，512 维）作为语义增强，仍是 CPU 推理
- **内容复用三道防线**：检索出的参考片段有防抄袭保护，避免生成结果过度复制语料原文

这个"本地优先、远程可选"的架构决策让 Style Engine 在断网环境完全可用，也规避了百万字语料上传远程的隐私问题。

### 2.2 轻量桌面架构

- **Tauri 2 + Flask Sidecar**：Rust 壳仅 177 行，安装包体积约为 Electron 同类方案的 1/5~1/10，内存占用低
- **进程生命周期绑定**：关闭窗口即清理全部子进程，不留后台残留
- **Flask 单服务**：页面与 API 同端口，天然无跨域；运行时仅 4 个 Python 依赖（flask/flask-sqlalchemy/olefile/numpy），攻击面小、打包简单

### 2.3 AI 在本项目中的双重角色

**AI 作为产品能力**（面向用户）：
- LLM 生成初稿、执行风格重写和去 AI 味改写
- Style Card 可选 LLM 增强描述（本地特征为主，LLM 仅做润色）

**AI 作为开发手段**（面向开发者本人）：
- Trae + DeepSeek V3 Pro 生成 80%+ 业务代码
- VSCode + Codex 做第二视角代码审查
- 人负责架构决策与逻辑把关——"我不写代码，但我读每一行代码"

这个项目本身就是 "AI 辅助开发" 与 "AI 交付产品" 的双层样本。

## 三、落地价值

### 3.1 目标用户与场景

| 用户群 | 场景 | 价值点 |
|--------|------|--------|
| 网文作者 | 长篇连载、设定集管理 | 模板系统 + 版本树贴合真实写作习惯 |
| 同人创作者 | 特定文风模仿（原作风格） | Style RAG 导入原作语料，生成贴近原作风格 |
| 隐私敏感写作者 | 不愿作品上传云端 | 数据全本地，API Key 不落盘 |
| 成本敏感用户 | 不想订阅在线平台 | 自带 API Key 按量付费，无订阅费 |

### 3.2 现实价值

- **可交付性**：双击 EXE 即用，无需 Python/Node 环境——对非技术背景的写作者是硬需求
- **成本模型**：以 DeepSeek 为例，生成一章（约 3000 字）成本不足 1 分钱，对比在线写作平台月订阅（30~50 元）有数量级优势
- **MIT 开源**：代码可审计，社区可验证"数据不出本机"的承诺

## 四、迭代创新方向

按优先级排列的后续演进路线：

| 优先级 | 方向 | 说明 |
|--------|------|------|
| P0 | 本地模型接入（Ollama） | 支持完全离线生成，补全"本地优先"的最后一块拼图 |
| P1 | Style Engine M14+ | 现有 13 个里程碑已全部完成，可继续扩展特征维度（如对话节奏、意象密度） |
| P1 | 导出格式扩展 | EPUB / docx / 番茄小说平台格式，打通"写完即发" |
| P2 | 跨设备同步（可选） | 端到端加密的模板/记录同步，保持"本地优先"原则下的可选云能力 |
| P2 | 协作模板市场 | 匿名化模板分享，社区共建提示词资产 |

**迭代原则**：延续项目一贯约束——本地优先、向后兼容、不引入重依赖。每个迭代先更新 EXEC_PLAN 写清范围与验收标准，再动代码。
