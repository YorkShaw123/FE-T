# 01 模块映射表

> 目标：把现有 73 个 Python 文件逐一确定归宿，让"改造开始后每个文件放哪、怎么放"没有第二种答案。
> 前提：口径为 **L1 范式层 + L2 框架层全量对齐课件，L3 基础设施用适配器替换**；业务功能与 Tauri 壳不变。

## 0. 改造动作的五个词

| 动作 | 含义 | 是否改业务逻辑 |
| --- | --- | --- |
| 平移 | 内容基本不动，换路径、换 import | 否 |
| 平移改造 | 逻辑不动，但签名/同步→异步/ORM 风格要改 | 否（只改接口形态） |
| 包装 | 算法不动，外面套一层课件要求的接口（节点函数、Adapter 方法） | 否 |
| 拆分 | 一个文件按职责拆到多个位置 | 否（行为等价） |
| 重写 | 行为可能变化，需要重新设计（路由层、入口、迁移器） | 是 |
| 退役 | 合并进别处或删除 | 否（代码消失） |

判断标准只有一条：**算法与提示词属于资产，一律"平移/包装"；框架与协议属于脚手架，允许"重写"。**

## 1. 三条硬边界

1. **不动**：`server/static/**`（19 个前端模块）、`server/templates/index.html`、`src-tauri/**`、`src/index.html`。前端只允许改 SSE 事件名与新增调用，不迁 Vue。
2. **不破**：对外 URL 先保留 `/api/*` 旧路径，新路径并行挂载，前端零改动过渡。
3. **不重写**：`style_*` 全家桶（Style Engine M0–M19、Style RAG 检索栈）。它们只进 Adapter 或图节点，算法口径一字不改。

## 7. 依赖方向（防循环导入）

```text
api  →  agents  →  core  →  db
              ↘  services  ↗
        adapters  ←  core
```

禁止：`core` 导入 `agents`；`db` 导入 `api`；`adapters` 导入 `api`；任何 `services` 导入 `fastapi`。

落地时用一个 20 行的 AST 检查脚本卡住这条线，写进 CI，比人工 review 靠得住。

## 8. 兼容约定

1. **包根统一 `backend`**，所有导入都是 `from backend.xxx import ...`，不留 `server` 前缀。
2. **URL 双轨**：新路由挂 `/api/v1/*`；`api/legacy.py` 把旧 `/api/*` 映射到新实现，过渡期结束后整文件删除。
3. **环境变量**：`FLORA_*` 全部保留，`config.py` 里做字段别名；新增 `.env.local` 作为可选覆盖。
4. **数据目录**：仍是 `%USERPROFILE%\.flora-editor\data`，桌面端用户无感知。

## 9. 验收标准

- 每个现有文件在本文档中有且只有一个归宿，无孤儿；
- 依赖方向检查脚本通过；
- `benchmark_style_engine.py` 改造前后输出一致；
- 22 个测试文件全部有明确归属与负责人；
- 前端 19 个 JS 模块零改动（除 SSE 事件名）。
