## CloudStudio 云端部署适配（实训演示用途）

用户要求把 Flora_Editor（实训项目）部署到 CloudStudio，约束：**只新增文件、不改任何已有代码**。

关键事实与决策：
- 项目为 **Flask 单服务架构**：`server/app.py` 直接渲染 `server/templates/index.html` + `server/static/`，前端 API 全部走相对路径 `/api/*`。教程中的 `vite.config.ts` / `.env` / `request.ts`（Vite proxy 双端口方案）对本项目**不适用**。
- `app.py` 的 `__main__` 硬编码 `host='127.0.0.1'`，无法被 CloudStudio 访问 → 新增 `server/cloud_run.py` 入口，复用 `create_app('production')` 改绑 `0.0.0.0:8000`。
- app.py 设置 `X-Frame-Options: DENY`，可能阻断 CloudStudio 内置浏览器 iframe 预览 → cloud_run.py 中新增 after_request 钩子，加 `Content-Security-Policy: frame-ancestors *`（现代浏览器中 CSP 优先于 XFO）。
- 新增 `.gitattributes`（`*.sh text eol=lf`）保证 start.sh 在仓库为 LF；本地 core.autocrlf=true。
- 已本地验证：`/api/health` 返回 ok，首页 200（52KB），CSP 头生效。
